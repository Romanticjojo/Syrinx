# 方向 B「声波暗流」

> 强适配档（Spotify 词汇 + Syrinx 主题化）。打开 `preview.html` / `perform.html` 查看。

## 设计立场

Spotify 式"内容优先黑暗"：UI 隐入近黑，**每曲一个主题色**是唯一色彩来源——封面、光晕、光标、高亮、进度条全部由曲目主题色驱动（本曲 Lumière = 晨光青绿 `#3ddfae`），氛围感与"每曲贴合主题"的需求同构。

## 关键选择

- **布局**：预览页 = 专辑详情式（巨幅方形封面 + 巨标题 + 大圆播放键 + Spotify 曲目列表式元数据行 + 卡片网格）；演奏页 = **无框全幅谱面**直接浮于暗底（上下渐变遮罩保可读）+ now-playing 控制条（左曲卡/中圆键/右工具）
- **排版**：DM Sans，粗细二元（700/400），紧凑字号域（11–76px），按钮大写 + 1.4px 字距
- **配色**：`#0e0e0e/#181818/#1f1f1f` 三级暗面 + 每曲主题色功能专用（不做装饰）+ 重阴影（0.3–0.5 透明度）
- **几何**：药丸（9999px）+ 圆形（50%）控制件，触感向
- **动效**：底部主题色光晕随"音频"呼吸（正式实现接 AnalyserNode FFT）、卡片 hover 浮起 mini 播放键、封面唱片标旋转
- **沉浸感策略**：演奏时谱子就是整个界面；主题色光晕从底部渗出，暗示音乐正在发生

## 权衡

- 强在：每曲主题色 = 系统级架构优势（一套 token 联动背景/光标/UI，服务 P0-7"每曲贴合风格的动态背景"）；演奏沉浸感最强；暗色体系对长笛夜曲气质契合
- 弱在：无框谱面在最华丽背景下的可读性风险（需渐变遮罩兜底，必要时降级为面板模式）；元数据列表式信息密度高、首屏不如 A 直白

## 适用于

"氛围即产品"的定位：用户为进入一首曲子的世界而来，UI 退到最后一层。
