# Syrinx UI 设计对比与定稿

> 2026-08-30 · 三方向对比（claude-design + popular-web-designs + sketch 技能流程产出）
> 每方向含 `preview.html`（入场预览页）+ `perform.html`（演奏界面），浏览器直接打开即可交互。

## 界面原型声明（Surface-first）

- **预览页 = Decide/Learn**：说服用户进入这首曲子——hero 构图正确，一条信息主线
- **曲库 = Explore**：卡片行/网格 + 扫读
- **演奏页 = Monitor + Command**：观看光标与小节推进、专注演奏——密度与可扫读优先，禁止营销框架

三个方向共享的硬约束（需求文档「关键体验原则」）：任何背景下谱面可读；谱/音/光标同源时钟；首页热闹、演奏页冷静。

## 取舍分析与定稿

**定稿：方向 B「声波暗流」为主体，融合 A 的两处保障。**

理由：

1. **"每曲主题色"是唯一的架构级差异**。需求 P0-7 要求"每首曲目配一个动态背景，贴合乐曲风格"——B 的主题色系统让背景光晕、谱面光标、小节高亮、进度条、控制条强调色全部由同一 token 驱动，换一首曲子整界面换一种氛围，恰好同构于 Spotify 的"专辑封面是唯一色彩来源"。A/C 都是全局一套色，每曲氛围只能靠背景素材单点实现。
2. **演奏页沉浸感契合"UI 是舞台不是主角"**。无框谱面 + now-playing 控制条把界面压到最薄层；A 的玻璃面板虽稳，但谱子像隔着窗看，与沉浸诉求相悖。
3. **C 的剧场概念好看但不可持续**。遮幅吃掉 13% 垂直空间对"读谱"是永久损失，仪式感会随日常使用衰减——保留其"开场字幕卡"气质用于**入场动画**，不做主界面。

融合 A 的两处保障：

- **入场仪式**：采用 A 的拼装动画流程（占位 CSS → 3D 长笛模型 → 用户外部视频），带"跳过/下次不再播放"
- **谱面可读性兜底**：无框谱面默认加三重保护——上下渐变 mask、谱面区域底部暗化、`prefers-reduced-motion` 降级；若某曲背景素材过于强烈，manifest 可开启"面板模式"降级（A 的玻璃面板作为 fallback 路径保留）

## 定稿设计 Token（实现依据）

```css
:root{
  /* 层级（B 系） */
  --bg:#0e0e0e; --surface:#181818; --surface-2:#1f1f1f;
  --ink:#ffffff; --ink-dim:#b3b3b3; --ink-faint:#7a7a7a;
  --border:#4d4d4d;
  /* 每曲主题色：Lumière = 晨光青绿；由 Song Manifest 提供，其他曲各配一色 */
  --accent:#3ddfae; --accent-deep:#0f5c46;
  --rec:#f3727f;
  /* 字体：标题 = 衬线（中文曲名的诗意），UI = DM Sans/系统黑体（B 的紧凑功能字） */
  --serif:Georgia,"Songti SC","Noto Serif SC",serif;
  --sans:'DM Sans',system-ui,'Segoe UI','PingFang SC','Microsoft YaHei',sans-serif;
  /* 几何与阴影（Spotify 系） */
  --pill:9999px; --circ:50%;
  --shadow-md:rgba(0,0,0,.3) 0 8px 8px;
  --shadow-lg:rgba(0,0,0,.5) 0 8px 24px;
}
```

主题色候选（每曲）：Lumière `#3ddfae`（晨光青绿）、夜曲/古典 `#8ea2ff`（月光蓝紫）、暖调民谣 `#e6a050`（炉火橙）、叙事曲 `#eb6e82`（玫瑰红）、练习曲 `#6edce8`（晨雾青）。
