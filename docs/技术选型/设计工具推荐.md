# 设计工具推荐 · UI 初稿 / 曲谱界面初稿产出路线

> 目的：为后续「UI 初稿」「曲谱界面初稿」两个任务选择合适的 Hermes skill/工具组合。
> 本项目设计基调：Netflix/Spotify 式暗色沉浸 UI，演奏页以谱面可读为最高优先。

## 技能对比与适用场景

| Skill | 输出物 | 适用场景 | 对本项目 |
|---|---|---|---|
| **claude-design** | 完整单文件 HTML 高保真稿（内嵌 CSS/JS），有完整设计方法论（先定表面类型→定 token→产出→防 AI 味自检） | 从零设计一个页面/交互原型，无既定品牌时 | ★ 主力。曲库首页、预览页、演奏页初稿都用它 |
| **sketch** | 2–3 个不同立场的可交互 HTML 变体 + 对比表 | 方向未定时做 A/B 对比（如"沉浸影院风 vs 工具简洁风"） | ★ 首页与演奏页**第一轮**用：各出 2–3 变体选方向 |
| **popular-web-designs** | 54 个真实产品设计系统模板（Stripe/Linear/Spotify…）精确 CSS token | "要 XX 那种感觉"时直接取 token | ★ 辅助。基调是 Netflix/Spotify 暗色：直接取 `spotify.md`（暗底绿点缀→改为暖金/青点缀）、`linear.app.md`（暗色精准感）作视觉词汇 |
| design-md | DESIGN.md token 规格文件 | 需要沉淀正式 token 文件入库时 | 选定方向后用它把最终配色/字体固化为 DESIGN.md |
| excalidraw | 手绘风线框/流程图 | 信息架构、用户流程图 | 可选：把需求文档第 4 节流程画成图 |

## 推荐组合路线

### 第一轮：方向探索（sketch × 2-3 变体 + popular-web-designs 供 token）

- 产出：`sketches/001-cinematic-dark/`、`001-clean-score-first/`、`001-warm-editorial/`（示例命名）
- 流程：claude-design 的工作方法（先声明表面类型）+ popular-web-designs 的 Spotify/Linear token 打底 + sketch 的变体纪律（不同立场，不是换配色）
- **演奏页是核心**：先集中探索演奏页（谱面+背景+控件的叠加关系），首页/预览页跟随演奏页定下的语言
- 验收：每个变体必须模拟"谱面上叠加动态背景"的效果（可用静态渐变假背景），直接检验可读性约束

### 第二轮：定稿细化（claude-design 单独出各页面完整稿）

- 产出：曲库首页.html、预览页.html、演奏页.html、回放页.html（含 hover/加载/空态/移动端断点）
- popular-web-designs 继续供给组件级 CSS（按钮、卡片、滚动条、控制条）

### 第三轮（可选）：token 固化（design-md）

- 把胜出稿的颜色/字体/间距导出为 DESIGN.md，进 repo 供 MVP 开发直接消费

## 具体建议（写给后续设计任务的要点）

1. 演奏页表面类型是 **Monitor/Operate 混合，以 Monitor 为主**——拒绝 hero、拒绝卡片栅格；控制条参照视频播放器而非 SaaS
2. 谱面可读性是硬约束：设计稿必须展示"背景最华丽时谱子仍清晰"的最坏情况（遮罩/局部暗化方案）
3. Netflix 悬停预览交互：首页卡片 hover 放大+视频起播，设计稿用 CSS transition + `<video>` 假数据即可表达
4. 视觉词汇锚点：暗底 #0e0e12 级别、单一强调色（建议暖金或晨光青，避开默认紫）、衬线大标题呼应"Nocturne"古典气质 + 无衬线正文
5. 素材占位：设计阶段用渐变/抽象 canvas 假背景与假封面，标注"正式素材由用户外部生成"
