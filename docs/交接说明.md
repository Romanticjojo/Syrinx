## 关键决策快照（已定，不要重新讨论）

1. **形态：Web SPA（PWA 方向）**，Vite + TypeScript + React + zustand
2. **曲谱引擎：OSMD**（MusicXML + 内置 cursor/自动滚动）
3. **同步架构：伴奏音频 Web Audio 时钟 = 唯一主时钟**；构建期生成小节时间表驱动光标
4. **录音：MediaRecorder**（关 AGC/降噪，只录麦克风）
5. **动态背景：每曲外部视频 + 暗化遮罩叠加**；shader 生成器是 P2
6. **素材引擎分离**：应用是播放器+同步引擎，动画/伴奏/背景都是 Song Pack 外部素材
7. MVP **不做**音高检测（P2 先 MPM/YIN，再考虑 CREPE）、不做账号/编辑器/社交

## 给「演奏核心 MVP」任务

- 里程碑 M1→M3 顺序见 需求文档.md 第 8 节；M2（同步演奏）是技术攻坚点，建议先做时间轴模块的单元测试
- Song Pack 格式按 需求文档.md 第 7 节实现 manifest 加载；首发示例曲 Nocturne pour Lumière 的曲谱/伴奏**由用户提供**，开发期可用任一公开 MusicXML 样例（OSMD 仓库自带样例）替代
- 已知坑：
  - OSMD 光标按音符位置推进，亚拍平滑移动需自行用 iterator 时间戳插值
  - 伴奏与谱不同源对不齐 → manifest 留 `offsetMs` 手动补偿
  - 录音必须 `echoCancellation/noiseSuppression/autoGainControl: false`
  - 时间/速度状态不要进响应式 store（rAF 每帧驱动，直接操作 DOM/SVG）
  - getUserMedia 需 https/localhost；本地开发用 `vite --host` 或起本地 https
- 蓝牙音频延迟：MVP 在设置里放延迟校准入口（可先留 TODO），提示文案推荐扬声器
